### 💡 一句话原则
> **LLM 生成的是"听起来合理的回答"，不是"一定正确的事实"。**

它像个很会说话但也会编故事的朋友。关键是要知道什么时候该信它、什么时候必须去查证。

### 🔑 几个必须知道的概念

**1. Token（词元）**
LLM 看文本不是按"字"看的，而是按 token。一个 token 大概相当于 0.75 个中文词或 0.25 个英文词。你发给模型的每句话、每个文档都被切成 token，这也决定了成本——token 越多越贵，模型能看进去的也有限。

**2. Embedding（向量化）**
就是把文字变成数学向量，让模型能判断"这两个东西像不像"。用来做搜索和匹配很好，但不能用来判断"对不对"。

**3. Hallucination（幻觉）**
模型会编造看起来合理但不真实的内容——比如编一个不存在的 API 函数、引用不存在的研究。这不是 bug，是模型的天性。解决方案：不要只靠 prompt 解决，要靠外部验证（查资料、看代码、人工确认）。

**4. 多模态**
除了文字，模型现在还能看图、听音频、读截图。对做产品的人来说，意味着可以处理更多类型的输入——比如截个图让模型解释。

### 在 AI × Web3 里 LLM 的位置
LLM 负责"理解和生成"，但不是整个系统：
- 数据层 ← RPC、预言机、文档
- **LLM 层 ← 理解、生成、规划**
- 执行层 ← 钱包、合约交互
- 安全层 ← 验证、权限控制、日志

> 离"实际执行"越近的操作，越不能只靠 LLM。
